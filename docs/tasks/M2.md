# Task: M2 (API: REST + read-only GraphQL)

Start only after the M0/M1 PR is merged. Read `AGENTS.md`, `docs/ARCHITECTURE.md` and `docs/data-notes.md` first.
Open two PRs: **M2a REST + search** first, then **M2b GraphQL + codegen**. Stop and report after each.

## Shared rules
- Async SQLAlchemy 2.x (asyncpg) in `apps/api`; one session per request. Reuse the M1 models, no duplicate schema.
- Money is integer para everywhere in responses (field names end in `_para` / `Para`); the web formats it.
- "Effective price" = `discounted` when it is set and the date (Europe/Belgrade today, or `as_of` in tests) is inside
  `[disc_from, disc_to]` (an empty bound is open); otherwise `regular`. One function, unit-tested, used by REST and GraphQL.
- Every price in a response carries its `list_date`; every response that shows prices carries `as_of`.
- Errors as RFC 9457 `application/problem+json`. Validate all input with Pydantic; hard caps listed below.
- `CORS_ORIGINS` from env. GET responses: `Cache-Control: public, max-age=300`. No auth, no write endpoints.
- Do not guess Strawberry or library APIs: check the installed version's docs and pin versions.

## M2a — REST + search
1. Migration: enable `unaccent`; add an IMMUTABLE SQL function `korpa_norm(text)` = lower, `đ`→`dj`, then unaccent
   (wrapper with an explicit dictionary so it can be used in indexes). Add a generated column `products.search_norm`
   (`korpa_norm(name || ' ' || brand)`), a GIN trigram index on it, and fill `search_tsv` with the `simple` config
   over the normalized text (GIN index). Explain in the PR why `simple` (no Serbian stemmer in Postgres).
2. `korpa_api/translit.py`: Cyrillic → Latin (Serbian rules, Љ→Lj, Њ→Nj, Џ→Dž, Ђ→Đ). Queries are transliterated, then
   normalized with the same rules as `korpa_norm` (Python twin, tested to match the SQL function on a word list).
3. `GET /api/search?q=&category=&limit=20&offset=0` (q 2–100 chars, limit ≤ 50, offset ≤ 1000).
   - 13 digits → exact barcode match only. Otherwise: full-text match OR trigram similarity, ranked by
     ts_rank + similarity, ties by name.
   - Item: barcode, name, brand, unit, category_code, min/max effective_para across formats, n_formats,
     any_discount, latest list_date. Response: items, total, as_of.
   - Must pass: `mleko`/`MLEKO` → "Mleko"; `cokolada` and `čokolada` → "Čokolada"; `шоколада` → "Čokolada";
     `djus` and `đus` → "Đus"; typo `cokolda` → "Čokolada"; unknown word → empty list, 200.
4. `POST /api/basket` body `{items: [{barcode, qty}]}` (1–50 items, qty 1–99, duplicates merged).
   For every retail format: total_para (effective × qty), found/missing barcodes, list_date range.
   Group by retailer. Rank complete baskets first by total, then partial ones by number found, then total.
   Never present a partial total as comparable to a complete one (`complete: bool` on each row).
5. `GET /api/categories`: code, name, n_products. `GET /api/quality`: per retailer, the last `ingest_runs` row
   (status, rows_total, rows_valid, errors by type, finished_at) and days since the newest `list_date`.
6. Tests (pytest against the Postgres service in CI): search cases above, effective price at window edges,
   basket ranking with complete/partial/missing items, problem+json on bad input, caps enforced.
7. Performance: `make seed-bench` generates a synthetic DB (~12k products × ~60 formats) and a small script measures
   p95 latency. Target < 200 ms locally for search and a 20-item basket. Put the numbers and `EXPLAIN ANALYZE` of the
   search query in the PR.

## M2b — GraphQL + codegen
8. Strawberry at `/graphql`, queries only (no Mutation type). GraphiQL only when `ENV=dev`. Introspection stays on.
   - `product(barcode)`, `products(barcodes: [String!]! ≤ 50)`, `categories`.
   - `Product`: barcode, name, brand, unit, category, names (per retailer), prices → [Price], cheapest,
     history(months ≤ 24) → monthly snapshots, changes(days ≤ 120) → price changes.
   - `Price`: format { id, name, retailer { name, slug } }, regularPara, discountedPara, effectivePara,
     unitPricePara, vat, discountFrom, discountTo, listDate.
9. DataLoaders created per request (context getter) for: prices by barcode, format by id, retailer by id,
   category by code, names, history, changes. Test: a query for 20 products with prices → format → retailer + history
   runs a constant number of SQL statements (count with a SQLAlchemy event listener; assert ≤ 8, same for 1 and 20).
10. Limits: `QueryDepthLimiter` (max 6), `MaxAliasesLimiter` (15), `MaxTokensLimiter` (1000), and a small static cost
    rule via `AddValidationRules`: each field costs 1, list fields multiply by their cap; reject cost > 5000 with a
    clear message. One test per limit showing a rejected query.
11. Schema export: `make schema` writes `apps/web/src/graphql/schema.graphql` (`strawberry export-schema`) and
    `apps/web/src/api/openapi.json`. Web: GraphQL Code Generator (`client` preset) + `openapi-typescript` →
    typed GraphQL documents and REST types; `npm run codegen`. CI regenerates both and fails on `git diff`.
12. `docs/adr/0001-rest-and-graphql.md` (half a page): why REST for flat cacheable reads and GraphQL for nested
    product reads, and what the limits protect against.
